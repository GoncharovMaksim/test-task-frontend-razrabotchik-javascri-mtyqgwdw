## 1. Что такое «строгий режим»? Для чего он нужен?

**Строгий режим (`"use strict";`)** — это режим выполнения кода, добавленный в стандарте ECMAScript 5 (ES5), который ограничивает использование устаревших и потенциально опасных возможностей JavaScript и включает строгую семантику.

### Зачем он нужен:
1. **Предотвращение случайного создания глобальных переменных:** Присвоение значения необъявленной переменной (`foo = 42;`) без strict mode неявно создает свойство в глобальном объекте (`window` / `global`). В строгом режиме выбрасывается `ReferenceError`.
2. **Превращение скрытых ошибок в исключения:** Попытка записи в свойства только для чтения (`read-only`), в геттер без сеттера или в замороженный объект (`Object.freeze`) вызывает явный `TypeError` вместо молчаливого игнорирования.
3. **Безопасное значение `this`:** В обычной функции, вызванной без контекста объекта (`fn()`), `this` равен `undefined`, а не ссылается на глобальный объект (`window` / `global`). Это защищает от непреднамеренной мутации глобального скоупа.
4. **Запрет небезопасного синтаксиса:**
   - Запрещен оператор `with`.
   - Запрещены восьмеричные литералы без префикса (например, `015` вызывает `SyntaxError`; разрешен только `0o15`).
   - Запрещено удаление неконфигурируемых свойств и обычных переменных через `delete name;`.
5. **Изоляция `eval`:** Переменные, объявленные внутри `eval()`, не утекают в окружающую область видимости.
6. **Резервирование ключевых слов:** Зарезервированы слова под будущие спецификации: `implements`, `interface`, `let`, `package`, `private`, `protected`, `public`, `static`, `yield`.

> *Примечание:* В ES6-модулях (`import` / `export`) и в телах ES6-классов строгий режим включен **автоматически по умолчанию**.

## 2. Переменные – в чем отличие var, let, const? Когда и что предпочтительнее применять?

| Критерий | `var` | `let` | `const` |
| :--- | :--- | :--- | :--- |
| **Область видимости (Scope)** | Функциональная (или глобальная) | Блочная (`{ ... }`) | Блочная (`{ ... }`) |
| **Всплытие (Hoisting)** | Всплывает, инициализируется в `undefined` | Всплывает, но попадает в TDZ | Всплывает, но попадает в TDZ |
| **Временная мертвая зона (TDZ)** | Нет | Да (обращение до объявления ➔ `ReferenceError`) | Да (обращение до объявления ➔ `ReferenceError`) |
| **Повторное объявление** | Разрешено в одном скоупе | Запрещено (`SyntaxError`) | Запрещено (`SyntaxError`) |
| **Переприсваивание значения** | Разрешено | Разрешено | Запрещено (ссылка неизменяема) |
| **Свойство глобального объекта** | Создает свойство в `window` при объявлении в корне | Не создает свойств в `window` | Не создает свойств в `window` |

### Что и когда применять:
1. **`const` (по умолчанию всегда):** Обеспечивает предсказуемость кода. Разработчик сразу видит, что ссылка не будет перезаписана. Мутировать внутренние поля объекта или элементы массива при этом можно (для полной неизменяемости используется `Object.freeze` / `as const` / `Readonly<T>`).
2. **`let` (только при необходимости переприсваивания):** Используется для счетчиков циклов (`for (let i = 0; ...)`), флагов-триггеров или локальных аккумуляторов.
3. **`var` (никогда в современном коде):** Устаревший синтаксис, приводящий к багам утечки области видимости из блоков `if`/`for` и отсутствию защиты от случайного повторного объявления.

## 3. Операторы сравнения

### В чем отличие `==` от `===`; `!=` от `!==`?
- **`==` и `!=` (абстрактное равенство / неравенство):** перед сравнением выполняют **неявное приведение типов (type coercion)** по правилам алгоритма Abstract Equality Comparison (ECMAScript 7.2.14). Если типы операндов не совпадают, движок преобразует один тип к другому (чаще всего к числу).
- **`===` и `!==` (строгое равенство / неравенство):** сравнивают операнды без приведения типов. Если типы различаются, `===` немедленно возвращает `false`, а `!==` возвращает `true`.

---

### Что будет в результате: `'01' == 1` и `'01' === 1`? Почему?
- `'01' == 1` ➔ **`true`**  
  *Почему:* При сравнении строки с числом через `==` строка преобразуется в число через внутреннюю функцию `ToNumber('01')`, что дает число `1`. Далее происходит сравнение `1 == 1`, результат которого `true`.
- `'01' === 1` ➔ **`false`**  
  *Почему:* Строгое сравнение проверяет совпадение типов. Тип левого операнда `string`, правого — `number`. Так как типы различны, результат `false`.

---

### Что будет в результате: `null === undefined` и `null == undefined`? Почему?
- `null === undefined` ➔ **`false`**  
  *Почему:* Разные типы (`Null` и `Undefined`).
- `null == undefined` ➔ **`true`**  
  *Почему:* В спецификации ECMAScript специальным правилом зафиксировано, что при нестрогом сравнении `null` и `undefined` равны друг другу и не равны никаким другим значениям в языке (кроме самих себя).

---

### Что будет в результате: `null > 0`, `null == 0`, `null >= 0`? Почему?
- `null > 0` ➔ **`false`**  
  *Почему:* Реляционные операторы (`<`, `>`, `<=`, `>=`) приводят операнды к числам: `ToNumber(null) === 0`. Получаем `0 > 0`, что является `false`.
- `null == 0` ➔ **`false`**  
  *Почему:* Оператор равенства `==` для `null` НЕ приводит его к числу! По правилам спецификации, `null` равен исключительно `undefined` или `null`. С любыми числами `null == x` дает `false`.
- `null >= 0` ➔ **`true`**  
  *Почему:* В спецификации ECMAScript оператор `>=` алгоритмически определен через отрицание оператора `<`: `a >= b` эквивалентно `!(a < b)`. Поскольку `null < 0` приводится к `0 < 0` (что дает `false`), отрицание `!false` возвращает **`true`**.

---

### Что будет в результате: `undefined > 0`, `undefined < 0`, `undefined == 0`? Почему?
- `undefined > 0` ➔ **`false`**
- `undefined < 0` ➔ **`false`**
- `undefined == 0` ➔ **`false`**  
*Почему:*
1. Для операторов сравнения (`>`, `<`) `undefined` преобразуется в число через `ToNumber(undefined)`, результатом чего является `NaN`. Любое математическое сравнение с `NaN` (`NaN > 0`, `NaN < 0`, `NaN >= 0`, `NaN <= 0`) всегда возвращает `false`.
2. Для оператора равенства `==`, как было отмечено выше, `undefined` равен только `null` и `undefined`. С числом `0` результат `false`.

## 4. Функции: можно ли сохранить функцию в переменную?

**Да, безусловно.** В JavaScript функции являются объектами первого класса (*first-class citizens*). Их можно:
1. Присваивать переменным:
   - **Function Expression:** `const fn = function() { ... };`
   - **Arrow Function:** `const fn = () => { ... };`
   - **Named Function Expression (NFE):** `const fn = function myFn() { ... };`
2. Передавать как аргументы в другие функции (колбэки, функции высшего порядка `map`, `filter`).
3. Возвращать из функций (замыкания, фабрики, каррирование).
4. Хранить в свойствах объектов и элементах массивов.

## 5. Функции колбэки: функция подтверждения действия через prompt

**ТЗ:** *«Напишите функцию, которая реализует подтверждение определенного действия (например, вы точно хотите удалить выбранный элемент?) в качестве параметров функция должна принимать: вопрос; функцию-колбэк, вызываемую если пользователь подтвердит действие; функцию-колбэк, вызываемую, если пользователь отклонит действие. Для подтверждения пользователем – используйте стандартную функцию prompt.»*

```typescript
type ConfirmCallback = (userInput: string) => void;
type CancelCallback = (userInput: string | null) => void;

function confirmAction(
  question: string,
  onConfirm: ConfirmCallback,
  onCancel: CancelCallback
): void {
  // Вызов стандартной функции prompt
  const result = window.prompt(`${question}\n(Введите "да" или "yes" для подтверждения)`);

  // Пользователь подтвердил, если ввел утвердительный ответ
  if (result !== null && (result.trim().toLowerCase() === 'да' || result.trim().toLowerCase() === 'yes')) {
    onConfirm(result);
  } else {
    // Если нажал "Отмена" (result === null) или ввел другое значение
    onCancel(result);
  }
}

// Пример использования:
confirmAction(
  'Вы точно хотите удалить выбранный элемент?',
  (answer) => console.log('Элемент успешно удален. Ответ:', answer),
  (answer) => console.warn('Удаление отменено. Ответ:', answer)
);
```

## 6. Объекты, методы объектов, this

### Что такое `this`?
`this` — это ключевое слово в JavaScript, которое ссылается на текущий контекст выполнения функции. В большинстве случаев значение `this` определяется **в момент вызова** функции (*runtime binding*), а не в момент ее объявления.

### Пример потери `this`:
Потеря контекста происходит при передаче метода объекта в качестве ссылки (например, в колбэк события или таймера):

```javascript
const developer = {
  name: 'Максим',
  greet() {
    console.log(`Привет, я ${this.name}`);
  }
};

// Вызов метода объекта: this указывает на developer
developer.greet(); // -> "Привет, я Максим"

// Потеря контекста: передача ссылки в setTimeout
setTimeout(developer.greet, 1000); 
// В строгом режиме -> TypeError: Cannot read properties of undefined (reading 'name')
// В нестрогом режиме -> "Привет, я undefined" (this === window)
```

### Решения проблемы потери `this`:

#### 1. Явная привязка контекста через `.bind()`:
```javascript
setTimeout(developer.greet.bind(developer), 1000);
// .bind() возвращает новую функцию с навсегда привязанным контекстом developer
```

#### 2. Стрелочная функция-обертка:
Стрелочные функции не имеют собственного `this`, а захватывают его лексически из окружающего контекста:
```javascript
setTimeout(() => developer.greet(), 1000);
```

#### 3. Объявление метода как стрелочного поля класса:
```typescript
class Developer {
  name = 'Максим';
  greet = () => {
    console.log(`Привет, я ${this.name}`);
  };
}
```

## 7. Планирование: setTimeout и setInterval

### Для чего используются:
- `setTimeout(fn, delay, ...args)` — планирует однократный вызов функции `fn` спустя не менее чем `delay` миллисекунд.
- `setInterval(fn, delay, ...args)` — планирует периодический циклический вызов функции `fn` каждые `delay` миллисекунд.

### В чем отличие `setInterval` от рекурсивного `setTimeout`?

1. **Момент отсчета интервала:**
   - В `setInterval` таймер следующего запуска начинает тикать **в момент старта** предыдущего выполнения. Если тело функции выполняется долго (например, 80мс при интервале 100мс), то зазор между завершением предыдущего и стартом следующего составит всего 20мс. Если выполнение займет дольше 100мс, вызовы начнут выполняться подряд без пауз.
   - В рекурсивном `setTimeout` планирование следующего шага происходит строго **в конце** выполнения предыдущего. Это гарантирует точную фиксированную задержку между *завершением* предыдущей операции и *стартом* следующей.

2. **Защита от наложения асинхронных задач:**
   - При запросах к серверу (fetch / axios) время ответа варьируется. С `setInterval` при сетевой задержке запросы могут накладываться. Рекурсивный `setTimeout` гарантирует, что следующий запрос пойдет только после того, как завершился предыдущий.

### Отмена timeout-а и interval-а:
При вызове возвращается числовой идентификатор таймера (`Timeout ID` в браузере или объект `Timeout` в Node.js). Отмена производится вызовами:
- `clearTimeout(timerId)`
- `clearInterval(intervalId)`

## 8. Что такое TypeScript? Для чего введен? В чем отличие от JS?

**TypeScript** — это строго типизированный язык программирования с открытым исходным кодом, разработанный Microsoft, представляющий собой статически типизированное надмножество (*superset*) JavaScript.

### Для чего введен:
1. **Обнаружение ошибок на этапе компиляции:** предотвращение опечаток в именах полей, неверных типов параметров и обращений к `undefined`.
2. **DX и поддержка IDE:** автодополнение (IntelliSense), автоимпорты, встроенная документация по типам.
3. **Безопасный рефакторинг:** переименование сущностей и изменение контрактов безопасно распространяются по всей кодовой базе.
4. **Самодокументируемый код:** сигнатуры функций и интерфейсы служат живой спецификацией системы.

### Отличия от JS:
- JS — язык с динамической и слабой типизацией. TS — язык со статической типизацией.
- Все типы в TS полностью стираются при компиляции (*type erasure*), в продакшен уходит чистый оптимизированный JavaScript без runtime-оверхеда по памяти и скорости.

## 9. Базовые типы TypeScript

1. **Примитивные типы:** `string`, `number`, `boolean`, `bigint`, `symbol`, `null`, `undefined`.
2. **Специальные типы:**
   - `any` — отключение проверки типов для переменной.
   - `unknown` — типобезопасный аналог `any`. Требует сужения типа (*type narrowing*) перед выполнением любых операций.
   - `void` — отсутствие возвращаемого значения у функции.
   - `never` — тип значения, которое никогда не может возникнуть (функция, выбрасывающая ошибку, бесконечный цикл или исчерпывающая проверка в switch-case).
3. **Составные типы:**
   - Массивы: `T[]` или `Array<T>`.
   - Кортежи (Tuples): массивы фиксированной длины с известными типами элементов, например: `[string, number]`.
   - Объекты: `object`, `{ key: string }`.
   - Перечисления (Enums): `enum Status { Active, Inactive }`.

## 10. Обобщенные типы (Generics) в TypeScript с примерами

**Generics (обобщения)** — это инструмент, позволяющий параметризовать типы. Они дают возможность писать повторно используемые функции, классы и интерфейсы, которые работают с различными типами данных, сохраняя строгую типобезопасность.

### Пример 1: Обобщенный контракт API-ответа
```typescript
interface ApiResponse<TData> {
  data: TData;
  status: 'success' | 'error';
  timestamp: number;
}

interface User {
  id: string;
  name: string;
}

// Использование:
const userResponse: ApiResponse<User> = {
  data: { id: 'u-1', name: 'Максим' },
  status: 'success',
  timestamp: Date.now(),
};
```

### Пример 2: Обобщенная функция с ограничением типа (`extends`)
```typescript
interface HasId {
  id: string | number;
}

function findById<T extends HasId>(items: T[], targetId: string | number): T | undefined {
  return items.find((item) => item.id === targetId);
}
```

## 11. Типы (`type`) и интерфейсы (`interface`) в TypeScript: отличия

| Критерий | `interface` | `type` (Type Alias) |
| :--- | :--- | :--- |
| **Основное назначение** | Описание формы объектов и контрактов классов | Описание любых типов (объекты, примитивы, объединения) |
| **Declaration Merging** | Поддерживается (два интерфейса с одним именем объединяются) | Запрещено (ошибка `Duplicate identifier`) |
| **Объединения и примитивы** | Не может напрямую объявить union (`A \| B`) или примитив | Легко объявляет: `type ID = string \| number;` |
| **Кортежи (Tuples)** | Нет специального лаконичного синтаксиса | `type Point = [number, number];` |
| **Наследование** | Через ключевое слово `extends` | Через оператор пересечения `&` |
| **Условные и mapped типы** | Нельзя использовать в определении интерфейса | Полная поддержка (`type Nullable<T> = ...`) |

## 12. Как сделать ряд свойств интерфейса необязательными? Как сделать все свойства необязательными?

### 1. Сделать ряд свойств необязательными:
Используется символ вопросительного знака `?` перед двоеточием:
```typescript
interface UserProfile {
  id: string;          // Обязательное
  fullName: string;    // Обязательное
  avatarUrl?: string;  // Необязательное
  bio?: string;        // Необязательное
}
```

### 2. Сделать все свойства интерфейса необязательными:
Используется встроенный утилитный тип `Partial<T>`:
```typescript
type OptionalUserProfile = Partial<UserProfile>;
```
*Под капотом `Partial<T>` устроен как Mapped Type:*
```typescript
type Partial<T> = {
  [P in keyof T]?: T[P];
};
```

## 13. Для чего нужен тип `Omit` в TypeScript?

`Omit<Type, Keys>` — это встроенный утилитный тип, который создает новый тип, выбирая все свойства из исходного типа `Type` и **исключая** указанные ключи `Keys` (строку или объединение строк).

### Практический пример:
При отправке формы регистрации нам не нужны системные поля сущности `id` и `createdAt`:
```typescript
interface UserEntity {
  id: string;
  name: string;
  email: string;
  passwordHash: string;
  createdAt: string;
}

// Тип для формы создания нового пользователя:
type CreateUserDto = Omit<UserEntity, 'id' | 'createdAt'>;
// Содержит только name, email, passwordHash
```

## 14. Возможно ли в TypeScript перегрузить функцию?

**Да, возможно.** В TypeScript механизм перегрузки функций (*Function Overloads*) реализуется через объявление нескольких **сигнатур перегрузки** (без тела) и последующей одной **сигнатуры реализации**, тело которой обрабатывает все возможные варианты.

### Пример реализации:
```typescript
// 1-я сигнатура перегрузки:
function formatValue(value: string): string;

// 2-я сигнатура перегрузки:
function formatValue(value: number): string;

// 3-я сигнатура перегрузки (массив):
function formatValue(value: string[]): string;

// Сигнатура реализации:
function formatValue(value: string | number | string[]): string {
  if (typeof value === 'string') {
    return value.trim();
  }
  if (typeof value === 'number') {
    return value.toLocaleString('ru-RU');
  }
  return value.join(', ');
}

// Использование:
const res1 = formatValue("  калуга астрал  "); // Тип возврата строго string
const res2 = formatValue(150000);              // Тип возврата строго string
```
Конечный потребитель функции видит только допустимые перегрузки в подсказках IDE, что исключает передачу неподдерживаемых типов данных.
